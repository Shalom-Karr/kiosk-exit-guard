Features

WebView2 kiosk window — new in v0.4.0

The kiosk page lives in this exe, not a Chrome subprocess. Fullscreen, topmost, frameless, JS-locked to refuse navigation away from the kiosk URL.

Chrome uninstalled on first run

The exe reads Chrome's UninstallString from the registry and runs the official Chrome uninstaller with --force-uninstall. Clean removal, idempotent if Chrome isn't installed.

Edge launches blocked at the OS

Sets HKLM\…\Image File Execution Options\msedge.exe\Debugger to redirect launches back to this exe with --silent-exit. Same for chrome.exe. Re-applied every launch in case Windows Update restores them.

UAC elevation

Embedded manifest. Every launch requests admin consent cleanly. The Task Scheduler entry uses HIGHEST run level, so logon launches are silent.

First-run setup wizard

No flags needed. Set password, set kiosk URL, then setup uninstalls Chrome, applies IFEO blocks, and registers the startup task — all in sequence.

HKLM password storage

Bcrypt hash in HKLM\Software\KioskExitGuard\PasswordHash. Admin-write only — a standard kiosk user can't bypass by deleting a config file.

Filter mode hotkey

Ctrl+Shift+Alt+K → password → flips ON/OFF. State persists across reboots.

Pause duration prompt

Toggling OFF asks "5m / 15m / 30m / 1h / Indefinite". Anything but Indefinite auto-re-enables when the timer fires.

Broad keystroke block

Filter mode ON: Alt+F4 password-gated; every other Ctrl/Win/Alt combo (Ctrl+F4, Alt+Tab, Win+R/E/D, …) silently swallowed.

Registry policy lockdown

Filter mode ON: DisableTaskMgr=1 and NoRun=1 under HKCU. Cleared when flipped OFF or via --reset.

How it works

One exe, three internal modes selected by the first command-line argument. The Task Scheduler entry only ever launches the controller; the other two are reached internally.

Controller — no args. Installed by Task Scheduler at logon. Owns the LL keyboard hook, the filter-mode state, the registry lockdown, and supervises the WebView2 child.
--webview — launched by the controller when filter mode flips ON. Opens the fullscreen WebView2 kiosk window. Exits when filter mode flips OFF (the controller kills it).
--silent-exit — how IFEO-blocked launches reach us. Windows passes the target exe's path as an extra arg. We exit immediately so the Chrome/Edge launch fails invisibly.

4. uninstall Chrome silently → 5. set IFEO Debugger for chrome.exe + msedge.exe → 6. install logon task

Runtime — filter mode OFF (default)

Controller running → keyboard hook installed but only watching for the toggle hotkey · IFEO blocks active · registry lockdown OFF · no WebView2 window

Runtime — filter mode ON

Controller spawns → --webview child (fullscreen WebView2 kiosk window)
Controller applies → HKCU DisableTaskMgr=1, NoRun=1
Controller swallows → Alt+F4 (→ password), Ctrl+anything, Win+anything, Alt+anything
Controller watchdog (30s tick) ensures the --webview child is still running. Respawns if killed.

Why not a child Chrome process anymore?

v0.3.0 launched chrome.exe --kiosk as a child. That worked, but it left Chrome installed and reachable as an escape vector — and uninstalling Chrome would break the whole thing. WebView2 is the same Chromium rendering engine packaged as an embeddable component instead of a standalone browser. By rendering the kiosk page through WebView2 inside our exe, we no longer depend on Chrome at all — so first-run can uninstall it and IFEO-block any reinstall.

WebView2 Runtime is pre-installed on every Win11 box and most current Win10 boxes (via Windows Update / Edge install). The exe doesn't ship a copy.

Setup

  1. Download the exe (button above) and place it in C:\Program Files\KioskExitGuard\.
  2. Double-click. Approve the UAC prompt.
  3. Set a password in the two prompts.
  4. Set the kiosk URL. Pre-filled with https://skluach.pages.dev/CMH/ — change it to your URL or accept the default.
  5. The exe will then silently uninstall Chrome (if present), block Chrome and Edge launches via IFEO, and register a logon task.
  6. Press Ctrl+Shift+Alt+K to flip filter mode on when ready.
SmartScreen warning on first launch. The exe is unsigned. Click More info → Run anyway. If Defender quarantines it, add the install directory to the exclusion list. (LL keyboard hook + unsigned exe matches keylogger heuristics — the alert is doing its job, but the exe is fine.)
WebView2 Runtime requirement. Pre-installed on every Win11 box and most updated Win10 boxes. If the kiosk window fails to open with a "WebView2 Runtime is not installed" message, grab the evergreen installer from developer.microsoft.com/microsoft-edge/webview2.

CLI flags

kiosk-exit-guard.exe                  # normal — controller + hook + watchdog
kiosk-exit-guard.exe --webview        # internal: renders the kiosk window (launched by controller)
kiosk-exit-guard.exe --silent-exit    # internal: IFEO Debugger redirect handler
kiosk-exit-guard.exe --set-password   # change the password (UAC-elevated)
kiosk-exit-guard.exe --set-url        # change the kiosk URL (UAC-elevated)
kiosk-exit-guard.exe --reset          # password-gated — clears registry policies, IFEO blocks, filter mode

--reset requires the configured password. If you've lost it entirely, an admin can wipe HKLM\Software\KioskExitGuard via regedit to fully reset the install and start over.

What it doesn't block

  • Ctrl+Alt+Del and Win+L are handled by Windows' Secure Attention Sequence, which sits below any user-mode hook. No user-mode tool can intercept them.
  • Booting from USB / safe mode bypasses everything. Set a BIOS password.
  • Another admin with an elevated terminal can still kill the exe. The Task Manager disable + IFEO blocks raise the bar for a standard kiosk user but don't stop another admin.
  • A third-party browser the kiosk user could somehow install would not be IFEO-blocked. (Standard accounts can't install software, so this is a low-probability path.)
